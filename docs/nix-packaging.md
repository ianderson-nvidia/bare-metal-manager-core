# Nix Packaging for Carbide

This document covers the Nix flake setup for bare-metal-manager-core,
the rationale behind design decisions, common problems when packaging
Rust projects with Nix, and remaining work.

## Overview

The flake provides:

- **Dev shell** (`nix develop`) — all build dependencies without
  system-level package installation
- **Cached builds** via crane's two-phase compilation (deps phase +
  source phase)
- **Rust binaries** (`nix build .#carbide-api`, etc.) — native x86_64
  and cross-compiled aarch64
- **Go binaries** (`nix build .#rest-api-api`, etc.) — static CGO=0
  binaries, both amd64 and arm64
- **OCI container images** (`nix build .#carbide-api-container`) built
  with nix2container; loaded via `nix run .#carbide-api-container-copy-to-docker`
- **SBOMs** (`nix build .#carbide-api-sbom`, `.#carbide-api-container-sbom`)
  generated by bombon with cargo-cyclonedx for full Rust crate coverage
- **iPXE EFI** (`nix build .#ipxe-efi-x86`, `.#ipxe-efi-aarch64`)

## Key concepts

### Flake inputs and pinning

`flake.nix` declares external dependencies (nixpkgs, crane,
rust-overlay, flake-utils). `flake.lock` pins each to a specific git
revision, the same role as `Cargo.lock`. Run `nix flake update` to bump
them.

### Crane two-phase builds

Crane splits Rust compilation into two derivations:

1. **`buildDepsOnly`** — compiles all workspace dependencies. Keyed on
   `Cargo.lock` and `Cargo.toml`. Cached until dependencies change.
2. **`buildPackage`** — compiles project source using cached dep
   artifacts. Only rebuilds when `.rs` files (or other source) change.

This means a source-only change skips the expensive dependency
compilation entirely.

#### How the two phases are wired up in `flake.nix`

The flake constructs two separate sources, one for each phase:

```nix
# Deps-only source: just Cargo.toml / Cargo.lock / rust-toolchain.
# cleanCargoSource strips every .rs file and non-cargo-metadata file,
# so editing source code does not invalidate this source's hash.
depsSrc = craneLib.cleanCargoSource ./.;

# Full source: everything cargo needs to compile workspace crates
# (filtered via pkgs.lib.fileset — see "Source filtering" below).
src = pkgs.lib.fileset.toSource { ... };
```

And two derivations:

```nix
# Phase 1: compile all external dependencies, save target/ as a tarball.
# Keyed on depsSrc only. A .rs edit does NOT invalidate this.
cargoArtifacts = craneLib.buildDepsOnly (commonArgs // {
  src = depsSrc;
});

# Phase 2: compile a single workspace binary using the cached artifacts.
mkCrateBinary = { pname, cargoExtraArgs ? "" }:
  craneLib.buildPackage (commonArgs // {
    inherit pname cargoArtifacts;
    cargoExtraArgs = "--package ${pname} ${cargoExtraArgs}";
    doInstallCargoArtifacts = false;
  });
```

Reading the `buildPackage` call line by line:

- **`commonArgs // { ... }`** — the `//` operator merges two attribute
  sets. Takes everything from `commonArgs` (shared build environment:
  `src`, `buildInputs`, `nativeBuildInputs`, env vars, `postConfigure`)
  and overrides or adds a few per-binary settings.

- **`inherit pname cargoArtifacts;`** — Nix shorthand equivalent to
  `pname = pname; cargoArtifacts = cargoArtifacts;`. The `pname` comes
  from the function argument (`mkCrateBinary { pname = "carbide-api"; }`)
  and `cargoArtifacts` comes from the enclosing `let` binding. Passing
  `cargoArtifacts` is the key plumbing step — it tells crane to extract
  the cached deps tarball into `target/` before cargo runs.

- **`cargoExtraArgs = "--package ${pname} ${cargoExtraArgs}";`** — sets
  the extra flags crane passes to `cargo build`. The `${pname}`
  interpolation produces `--package carbide-api`, which tells cargo to
  build only one binary target instead of everything in the workspace.
  There's a (safe) name collision here: the attribute being set and the
  function parameter are both called `cargoExtraArgs`. Nix resolves the
  right side in the enclosing scope (the function parameter) and binds
  the result to a new attribute of the same name.

- **`doInstallCargoArtifacts = false;`** — crane can optionally save the
  post-build `target/` as a new cargo-artifacts output, letting you
  chain derivations. Each binary in the flake is a terminal derivation
  (nothing else depends on its `target/`), so we skip this to save time
  and disk space.

#### What happens at build time

When you run `nix build .#carbide-api`, crane:

1. **Unpacks source** — the filtered `src` goes into the build directory
2. **Extracts `cargoArtifacts`** — the deps tarball (`target.tar.zst`)
   is unpacked into `target/`. This is the cache win: all external deps
   are already compiled.
3. **Runs `postConfigure`** — Kea library symlinks, etc.
4. **Runs `cargo build --release --package carbide-api`** — cargo sees
   the precompiled deps in `target/`, skips them, and only compiles
   workspace crates
5. **Installs the binary** — `target/release/carbide-api` → `$out/bin/`
6. **`autoPatchelfHook`** — rewrites the binary's RPATH to point at the
   Nix store paths for `libtss2-*`, `libgcc_s`, etc., so the binary
   finds its shared libraries at runtime without `LD_LIBRARY_PATH`

#### Cache invalidation behavior

| Change | `cargoArtifacts` | `buildPackage` | Approx. time |
|---|---|---|---|
| Edit one `.rs` file | cache hit | rebuild | ~2-3 min |
| Edit `README.md`, `.github/`, `docs/` | cache hit | cache hit | seconds |
| Add a dep to a `Cargo.toml` | **rebuild** | rebuild | ~15 min |
| Bump a version in `Cargo.lock` | **rebuild** | rebuild | ~15 min |
| First build / cold cache | build | build | ~15 min |

The typical workflow is that `Cargo.lock` rarely changes, so most
iterations hit the deps cache and only pay the ~2-3 minute workspace
rebuild cost. Add a Nix binary cache (S3, Cachix, Attic) and even the
cold-cache cost drops to a download.

#### Writing generated code to `OUT_DIR`, not `src/`

If a `build.rs` writes generated code back into its own source tree
(e.g., `src/protos/foo.rs`), crane's caching breaks — each build uses
a fresh Nix sandbox tmpdir, so cargo sees different source paths and
re-fingerprints everything. The fix is to follow cargo's convention
and write generated code to `OUT_DIR` instead:

```rust
// In build.rs
let out_dir = PathBuf::from(env::var_os("OUT_DIR").unwrap());
tonic_prost_build::configure()
    .out_dir(&out_dir)  // not "src/protos"
    .compile_protos(...)?;

// In src/protos/mod.rs — pull the generated files from OUT_DIR
pub mod common {
    include!(concat!(env!("OUT_DIR"), "/common.rs"));
}
```

This is the standard cargo convention used by `prost-build`,
`tonic-build`, `bindgen`, etc. Writing to `src/` only works in
mutable-source-tree environments and breaks hermetic builds (Nix,
Bazel, reproducible CI).

### Source filtering

Nix hashes the source tree to determine cache keys. Including
irrelevant files (CI configs, docs, helm charts) would cause
unnecessary cache invalidation. The flake uses two filters:

- **`craneLib.filterCargoSources`** — includes `.rs`, `Cargo.toml`,
  `Cargo.lock`, and related Rust files
- **`extraFilter`** — includes additional non-Rust files needed by
  `build.rs` scripts and `include_str!`/`include_bytes!` macros (files
  under `crates/`, `templates/`, `test-certs/`, `proto/`, `migrations/`)

**Important**: Nix flakes only see git-tracked files. New files must be
at least staged (`git add`) before `nix build` can see them.

### Container images with nix2container

`nix2container` builds OCI images natively without a Docker daemon:

- Each `/nix/store` path becomes its own layer (up to `maxLayers = 100`),
  so a single binary rebuild only invalidates one layer in the registry
- No base image, no `apt-get`, no package manager in the image
- Images are minimal (only what the closure needs) and reproducible
  (same `flake.lock` = identical image)
- Loaded via the patched `skopeo-nix2container` using the `nix:` transport:
  `nix run .#<name>-container-copy-to-docker`

Each container also includes:

- **OSRB attribution SBOM** at `/usr/share/carbide/attribution.cdx.json`
  generated by bombon with cargo-cyclonedx data for all Rust crates
- **OSS source tarballs** at `/usr/share/oss-sources/` for all runtime
  packages (required by OSRB NVBug 5717738)

Per-service runtime dependencies are declared in `serviceRuntime` in
`flake.nix`. Services not listed there get only their binary's own
`/nix/store` closure plus `cacert`.

### Versioning

The flake derives version from git state:

- Clean commit: uses `self.shortRev` (7-char commit hash)
- Dirty tree: uses `self.dirtyShortRev` (hash + `-dirty` suffix)
- No git info: falls back to `"dev"`

This version is used for both Nix derivation names and container image
tags.

## Common problems when Nix-packaging Rust projects

### GitHub API rate limits

Nix fetches flake inputs via the GitHub API, which has aggressive
anonymous rate limits. Set an access token:

```sh
export NIX_CONFIG="access-tokens = github.com=$(gh auth token)"
```

For Docker builds, either pass the token as a build secret or defer
package installation to first-run scripts that can access mounted `gh`
credentials.

### Nix store immutability and build scripts

The Nix store (`/nix/store/`) is read-only. Build scripts (`build.rs`)
that write to their own source directory fail with "Permission denied"
when the crate is vendored into the store.

**Symptoms**: `Permission denied` errors from `build.rs` during
`buildDepsOnly` or `buildPackage`.

**Root cause**: The upstream crate writes generated code to `src/`
instead of `OUT_DIR`.

**Workaround**: In `postConfigure`, copy the vendor directory to a
writable location and redirect cargo's config:

```nix
postConfigure = ''
  storeDir=$(grep -oP 'directory = "\K/nix/store/[^/"]+' \
    .cargo-home/config.toml | head -1)
  if [ -n "$storeDir" ] && [ -d "$storeDir" ]; then
    writable="$TMPDIR/writable-vendor"
    cp -rL "$storeDir" "$writable"
    chmod -R u+w "$writable"
    substituteInPlace .cargo-home/config.toml \
      --replace-fail "$storeDir" "$writable"
  fi
'';
```

**Proper fix**: Submit a PR upstream to write generated code to
`OUT_DIR` instead of `src/`. The `OUT_DIR` environment variable is
provided by cargo for exactly this purpose.

### Test-only crates without `src/`

Crates that only have a `tests/` directory (no `src/lib.rs` or
`src/main.rs`) break crane's dep-building phase. Crane creates dummy
source stubs based on the manifest, but can't handle crates with no
declared targets.

**Symptoms**: `no targets specified in the manifest` during
`buildDepsOnly`.

**Fix**: Add an empty `src/lib.rs` to the crate:

```rust
// Intentionally empty — this crate only contains integration tests in tests/.
// This file exists so cargo can parse the workspace manifest when source files
// are stripped (e.g., by crane's buildDepsOnly phase in the Nix build).
```

### Missing non-Rust source files

Rust code using `include_str!`, `include_bytes!`, or build scripts that
read data files will fail if those files are excluded by the source
filter.

**Symptoms**: `couldn't read "path/to/file.ext": No such file or
directory` at compile time.

**Fix**: Expand the source filter to include the relevant files or
directories. The current flake takes a broad approach — including
everything under `crates/`, `templates/`, `test-certs/`, `proto/`, and
`migrations/` — rather than enumerating individual extensions, to avoid
repeated breakage.

### Shared libraries not found at test runtime

Compilation links against Nix-provided libraries via `pkg-config`, but
test binaries need to find those `.so` files at runtime. The Nix store
paths aren't on `LD_LIBRARY_PATH` by default.

**Symptoms**: `error while loading shared libraries: libfoo.so.N:
cannot open shared object file` when running tests (not during
compilation).

**Fix**: Set `LD_LIBRARY_PATH` in `commonArgs`:

```nix
LD_LIBRARY_PATH = pkgs.lib.makeLibraryPath buildInputs;
```

`makeLibraryPath` generates a colon-separated list of `lib/` directories
from all packages in `buildInputs`.

### sqlx compile-time database checks

`sqlx` can verify SQL queries at compile time by connecting to a
database. This isn't possible in a Nix build sandbox (no network
access).

**Fix**: Set `SQLX_OFFLINE = "true"` in `commonArgs`. For full
compile-time verification, run `cargo sqlx prepare` to generate a
`.sqlx/` directory with cached query metadata and commit it to the
repository.

## Devcontainer integration

The devcontainer includes Nix via the Determinate Systems installer
(`--init none` for container environments without an init system). Key
details:

- `/nix` is persisted as a Docker volume to avoid re-downloading the
  store on container rebuilds
- Nix store ownership is set to the dev user (`chown -R`) for
  single-user mode
- `nixd` and `nixfmt-rfc-style` are lazily installed on first
  interactive shell if not already present, using `gh auth token` for
  GitHub API authentication
- VS Code uses the `nix-ide` extension (`jnoortheen.nix-ide`) with
  `nixd` as the language server
- RustRover uses the NixIDEA plugin (installed manually, persisted via
  `jetbrains-cache` volume)

## Remaining work

### Runtime deps per service

`serviceRuntime` in `flake.nix` is mostly empty. As deployments confirm
what each binary shells out to at runtime, add entries:

```nix
serviceRuntime = {
  carbide-scout = with pkgs; [ tpm2-tools ipmitool ];
};
serviceExtraCommands = {
  carbide-dhcp = "mkdir -p var/run/kea";
};
```

### Nix package discovery

To find which nixpkgs package provides a specific file (e.g., a shared
library), install `nix-index`:

```sh
nix profile install nixpkgs#nix-index
nix-index  # builds the database
nix-locate libkea-dhcp4.so
```

Or search online at https://search.nixos.org/packages.
